# 01. Technical Assignment (ТЗ)

## 1. Goals

- Give people in Dushanbe (and students at the university) one simple place to post and find local announcements.
- Work well on laptop **and** phone (mobile-first), in Tajik, Russian and English.
- Be deployed and usable by any real visitor at the end of day 12–14.
- Cost nothing: free plans only, no card, no domain.

## 2. Target users

| User                  | Needs                                                                |
| --------------------- | -------------------------------------------------------------------- |
| Students              | Find tutors, rentals near campus, lost items; post own announcements |
| Residents of Dushanbe | Rentals, lost & found, local services                                |
| Tutors                | Offer lessons with price per hour and contact                        |
| Landlords             | Post rentals with price per month, photos, map pin                   |

## 3. Roles

Plan update (2026-10-28): **the site is for logged-in people.** A visitor who is not logged in only sees the About page. Everything else needs a login.

| Role             | Can do                                                                                                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Guest            | See the About page (what the site is, the 4 categories, how it works, safety, posting rules), change language/theme, log in or create an account. Nothing else.                                                               |
| User             | Browse and read posts and profiles; create/edit/delete own posts; comment, favorite, report, message, notifications; edit own profile (username, password, picture); log out                                                  |
| Verified student | A user with a verified university email: shows a "Student ✓" badge. **Not a role**: it is a flag (`isStudentVerified`) on a user or admin                                                                                     |
| Admin            | Everything a user can, plus the admin panel: reports, remove/restore posts, block/unblock **normal users**, stats, admin post and user pages                                                                                  |
| Super admin      | The owner, forever, exactly one account (the email in `SUPER_ADMIN_EMAIL`). Everything an admin can, plus: block/unblock/touch other admins, make a user an admin, remove an admin's role. Nobody can change the super admin. |
| Blocked user     | Cannot log in; existing sessions are refused; cannot create content                                                                                                                                                           |

Nobody can choose a role when signing up (everyone is USER) and no endpoint accepts a role in its request body.

## 4. User stories and acceptance criteria

"Acceptance" always means: works in Swagger (backend) **and** on mobile (360px) and desktop (1280px) (frontend), in all 3 languages, no hardcoded text.

### Phase 1: MVP

## 5. Functional requirements (summary)

- Auth with a short JWT (15 min) and a rotating refresh token, both in httpOnly cookies; bcrypt (cost 10+).
- Login-only access: only `GET /api/health` and the auth endpoints are public.
- Roles USER, ADMIN, SUPER_ADMIN (one, from `.env`).
- REST API under `/api`, documented in Swagger for every endpoint.
- Backend sends stable error codes, never UI text.
- Posts: CRUD, filters, search, sort, pagination, counts, resolve, renew, expiry.
- Uploads through the backend to Cloudinary.
- Notifications, messages through REST + polling (no WebSockets in v1).
- Admin role with its own guard.

## 6. Non-functional requirements

| Area          | Requirement                                                                                                                                              |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Security      | OWASP basics; helmet; CORS with credentials; rate limiting; bcrypt; validation on every input; file type and size checks; IDOR checks; no secrets in Git |
| Performance   | Lighthouse mobile: Performance ≥ 85. Lazy-loaded responsive images, skeletons, small JS. Pagination everywhere.                                          |
| Responsive    | Mobile (360–767), tablet (768–1023), desktop (1024+, max width ~1280). Tap targets ≥ 44px. Inputs ≥ 16px font.                                           |
| PWA           | Manifest (3 languages), icons 192/512/maskable, service worker, offline page, "Add to home screen" hint                                                  |
| Accessibility | WCAG AA basics: contrast ≥ 4.5:1, visible focus, labels on inputs, keyboard navigation, alt text, reduced motion. Lighthouse ≥ 90.                       |
| i18n          | tg, ru, en; no hardcoded text; `npm run i18n:check`                                                                                                      |
| SEO           | Public pages server-rendered; titles and meta descriptions translated; `hreflang`; `sitemap`; Lighthouse SEO ≥ 90                                        |
| Cost          | Free plans only                                                                                                                                          |

## 7. Out of scope (v1)

Native apps, WebSockets/push notifications, payments, translation of post content, email notifications other than verification, social login, paid features, moderation by AI, deleting an account, changing the login email, password-reset by email.

## 8. Future upgrades

WebSockets for chat, React Native app, push notifications, automatic translation of posts, own domain.
